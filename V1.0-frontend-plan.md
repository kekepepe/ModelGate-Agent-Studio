## P1 — live updates + Sidebar "current task" (~60 min)

Two related gaps: live SSE consumption, and a Sidebar line showing
what each Station is currently doing.

### P1-1 SSE → BottomConsole 实时事件流 (~30 min)

**Why**: backend exposes `GET /runtime/events/{goal_id}` (text/event-stream)
since V1.0-2. Frontend ignores it; BottomConsole polls on a timer.
This is the "live updates" promise V1.0-2 made.

**Frontend**:
- New `frontend/src/hooks/useRuntimeEvents.ts`:
  - takes a `goalId: string | null`
  - returns `{ events: RuntimeEvent[], isConnected: boolean }`
  - on mount opens `new EventSource(...)`, parses
    `event: <type>\ndata: <json>\n\n` frames, accumulates into state
  - closes on unmount or `goalId=null`
  - re-opens if the goalId changes
  - re-uses `useWorkspaceState`'s refetch on each event (so React Query cache stays in sync)
- `frontend/src/components/BottomConsole.tsx`:
  - replace the `refetchInterval: 2000` TanStack Query polling with the
    new SSE hook
  - when SSE is `isConnected=true`, show a small green pulse next to
    the console title; when false (or after a disconnect), fall back to
    a 5s polling interval as a safety net
- `useRuntimeEvents` exports the typed `RuntimeEvent` interface
  (reuse `event_type` / `event_status` enum values already in
  `src/types/log.ts`).

**No backend change.** The endpoint already exists.

**Acceptance**: open `/workspace/runs/:runId` in two browser tabs; start a
new Run; both tabs' BottomConsole must show the same event stream
within 1s, and the on-screen "Last update" timestamp must update
without page reloads.

### P1-2 `/api/v1/tasks` list + Sidebar "current task" line (~30 min)

**Why**: ActiveStationsSidebar (V1.0-6a) shows Station name + state, but
"what is each Station doing right now?" requires a per-Station
"current task" line. There's no `/api/v1/tasks` LIST endpoint today,
only `GET /tasks/{task_id}` and per-goal workspace state.

**Backend**:
- New endpoint `GET /api/v1/tasks?agent_id=...&status=running,assigned,pending&page_size=50`
  in `backend/src/routes/tasks.py` (or a new `backend/src/services/task_query_service.py`).
  Filters: `agent_id` (multi), `status` (CSV), `goal_id`, pagination.
  Default ordering: `status` rank (running > assigned > pending > ...) then
  `priority DESC, updated_at DESC`.
- Reuse the existing Task SQLAlchemy model + schemas. The endpoint
  returns the same shape as `/api/v1/goals/{id}/state` task list (so
  frontend can reuse `WorkspaceTask`).
- Migration: **none**. New endpoint only.

**Frontend**:
- New `frontend/src/hooks/useTasks.ts` (rename the future
  `useWorkspaceTasks` we sketched in V1.0-6a):
  - `useTasks({ agentIds: string[], statuses: TaskStatus[], pageSize })`
  - TanStack Query, 5s staleTime, 30s refetchInterval
- `frontend/src/components/app-shell/ActiveStationsSidebar.tsx`:
  - For each Station row, look up the highest-ranked task whose
    `assigned_agent_id` matches
  - Render under the role line: a one-line `→ {task.title}` truncated
    with a Tooltip on hover
  - If no task, show `→ (空闲)` (already in the design)
- Strip the `(空闲)` italic placeholder when the API is in flight;
  instead show a 6px gray skeleton bar.

**Acceptance**: with the demo stack running and a Goal executing,
every Station row in the Sidebar shows the current task title; after
the Run finishes, the row returns to `(空闲)`.
