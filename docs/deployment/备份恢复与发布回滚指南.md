# 备份、恢复与发布回滚指南

## 发布前备份

记录当前 Git SHA、镜像 digest、Alembic revision、环境变量版本和备份校验和。停止写入后备份数据库。

SQLite：

```bash
docker compose stop backend
mkdir -p backups
docker run --rm -v modelgate-agent-studio_modelgate-data:/data:ro \
  -v "$PWD/backups:/backup" alpine \
  sh -c 'cp /data/modelgate.db /backup/modelgate-before-release.db'
docker compose start backend
```

PostgreSQL：

```bash
pg_dump --format=custom --no-owner --file=modelgate-before-release.dump "$DATABASE_URL"
```

备份必须在隔离环境至少恢复一次，随后运行 `alembic current`、`python scripts/database_smoke.py` 和 API smoke。

## 应用回滚

1. 停止接收新 Goal，等待运行中不可重放 Tool 完成或人工中止。
2. 保存 ExecutionLog、失败截图和当前数据库备份。
3. 将镜像回滚到已记录 digest；不要使用浮动 `latest`。
4. 仅当该 migration 明确支持 downgrade 时执行 `alembic downgrade <revision>`。
5. 若 migration 为 forward-only，恢复发布前数据库备份，并部署与该备份 schema 匹配的镜像。
6. 启动后检查 `/health`、migration revision、Provider health、Workspace 状态与一个只读 direct Goal。

## 数据恢复注意事项

- 恢复会覆盖备份之后写入的数据，必须先取得操作批准并保存现状快照。
- 不允许在未验证备份的情况下删除 volume 或执行 `docker compose down -v`。
- 已完成且带外部副作用的 Tool 不因数据库恢复自动重放；依照 ToolCallRecord 和 idempotency key 人工核对。
- 回滚后保留事件时间线，记录受影响 Goal、恢复点和人工介入。
