# 核心用户流程文档

> 🎯 **本文档定义用户使用产品时的标准操作流程。**
>
> 每条流程都精确到：用户点哪里 → 系统发生什么 → 页面怎么变 → 用户看到什么。

---

## 流程 A：创建 Goal 并启动任务

### 前置条件

- 用户已打开 Workspace 页面
- 已配置至少一个模型 Provider

### 完整流程

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 用户输入目标                                               │
│                                                             │
│   用户操作：                                                  │
│   → 点击左侧「输入目标」文本框                                │
│   → 输入："帮我设计一个 Next.js + FastAPI 项目的 Workspace 页面"│
│   → （可选）设置任务优先级、允许的模型、是否允许 Handoff       │
│   → 点击「开始」按钮                                          │
│                                                             │
│   系统响应：                                                  │
│   → Goal 状态：created → planning                           │
│   → 生成 Goal ID，保存到数据库                                │
│   → Router Agent 开始分析任务类型                             │
│                                                             │
│   页面变化：                                                  │
│   → 输入区收起，显示「正在分析任务...」                       │
│   → 顶部状态栏显示：Planning 阶段                             │
│   → Planner 工位灯从灰色 → 蓝色闪烁                          │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 2. Planner 拆解任务                                           │
│                                                             │
│   系统响应：                                                  │
│   → Planner Agent 调用模型，生成任务拆解                       │
│   → 生成 3~5 个 Task 对象                                    │
│   → 每个 Task 有：title、description、assigned_agent、priority│
│   → Task 状态统一设为 pending                                 │
│                                                             │
│   页面变化（Card Flow View）：                                 │
│   → Workspace 中间动态生成 Agent Cards                        │
│   → Planner Card 显示「拆解完成」                               │
│   → 任务卡片依次排列，颜色都是灰色（pending / queued）         │
│   → 左侧 Task Tree 显示所有 Task 列表                         │
│                                                             │
│   页面变化（Pixel Office View）：                              │
│   → Planner Worker 从大门进入工位                              │
│   → 开始拆解动作动画                                           │
│   → 其他工位保持 idle 状态                                    │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 3. 任务开始执行                                               │
│                                                             │
│   系统响应：                                                  │
│   → 第一个 Task 状态：pending → assigned → running          │
│   → 对应 Agent Station 状态：idle → busy                    │
│   → Worker Session 创建                                      │
│   → 开始调用模型执行任务                                      │
│                                                             │
│   页面变化（Card Flow View）：                                 │
│   → 第一个任务卡片：灰色 → 蓝色（带呼吸动画）                  │
│   → 卡片上显示：正在执行... + 当前模型名称                      │
│                                                             │
│   页面变化（Pixel Office View）：                              │
│   → 对应 Worker 从大门进入工位                                │
│   → 工位状态灯：灰色 → 蓝色闪烁                              │
│   → 小人开始敲击键盘动画                                       │
│   → 工位上方浮动当前 Task 标题                               │
│                                                             │
│   两个视图共有：                                             │
│   → 底部日志区新增：「Coder Agent 开始执行 Task-xxx」          │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 4. 任务完成并流转                                             │
│                                                             │
│   系统响应：                                                  │
│   → Agent 生成输出，更新 Task.output                         │
│   → Task 状态：running → completed                          │
│   → Agent 状态：busy → idle                                 │
│   → 触发下一个 Task 开始执行                                  │
│                                                             │
│   页面变化（Card Flow View）：                                 │
│   → 任务卡片：蓝色 → 绿色                                    │
│   → 卡片上显示对勾 +「完成」                                  │
│   → 完成的 Agent Card 缩略到底部 Completed Agents 区域        │
│   → 下一个任务卡片自动变蓝色开始执行                           │
│                                                             │
│   页面变化（Pixel Office View）：                              │
│   → 工位状态灯：蓝色 → 绿色（短暂）→ 灰色                     │
│   → Worker 完成动画：背靠椅子 + ✓ 气泡，然后淡出              │
│   → 下一个 Worker 从大门进入对应工位                          │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 5. Supervisor 最终审查                                       │
│                                                             │
│   系统响应：                                                  │
│   → 所有 Task 完成后，Supervisor Agent 启动                   │
│   → 审查所有输出，生成最终汇总                                 │
│   → Goal 状态：in_progress → reviewing → completed          │
│                                                             │
│   页面变化：                                                  │
│   → Supervisor 工位灯变蓝色                                   │
│   → 所有任务卡片都变成绿色                                    │
│   → 顶部显示「正在生成最终结果...」                            │
│   → 完成后显示最终汇总结果                                    │
│   → 出现「查看完整报告」「重新运行」「保存为模板」按钮           │
└─────────────────────────────────────────────────────────────┘
```

## 流程 B：Agent 执行任务（内部流程）

### 这是系统内部流程，用户不可见但决定了系统行为

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 接收任务                                                  │
│                                                             │
│   触发条件：Task 被分配给 Agent                               │
│   系统动作：                                                  │
│   → 从数据库读取 Task 完整信息                                │
│   → 读取 Agent Profile（角色、system prompt、工具权限）        │
│   → 读取 Goal 上下文和已完成 Task 的输出                       │
│   → 创建 Worker Session                                       │
│                                                             │
│   数据变化：                                                  │
│   Task.status: assigned → running                           │
│   WorkerSession.status: idle → running                       │
│   ExecutionLog: 新增「Agent 接收任务」记录                     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 2. 组装上下文                                                │
│                                                             │
│   系统动作：                                                  │
│   → 组装 System Prompt（Agent 角色定义）                      │
│   → 组装 Task 描述 + 约束条件                                 │
│   → 附加上下文：已完成 Task 的输出、Handoff 历史               │
│   → v0.1：暂时不加载 Memory（后续版本加）                     │
│                                                             │
│   输出：完整的 Prompt 字符串                                  │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 3. 选择模型                                                  │
│                                                             │
│   系统动作：                                                  │
│   → 读取 Agent 的默认模型配置                                 │
│   → 检查模型额度状态                                          │
│   → 如果额度不足：触发 Handoff（见流程 C）                    │
│   → 如果正常：选择该模型                                      │
│                                                             │
│   v0.1 简化：默认模型 + 手动切换，不做复杂路由逻辑             │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 4. 调用模型                                                  │
│                                                             │
│   系统动作：                                                  │
│   → 调用对应 Provider 的 API                                  │
│   → 记录请求参数、时间、token 用量                             │
│   → 处理超时、错误、重试                                      │
│                                                             │
│   数据变化：                                                  │
│   QuotaUsage: 新增 token 使用记录                            │
│   ExecutionLog: 新增「模型调用」记录                           │
│   WorkerSession: 更新 token_used 字段                        │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 5. 解析输出                                                  │
│                                                             │
│   系统动作：                                                  │
│   → 解析模型返回内容                                          │
│   → （如果需要）解析结构化输出（JSON）                        │
│   → 提取关键信息：是否完成、输出内容、遇到的问题               │
│                                                             │
│   数据变化：                                                  │
│   Task.output: 更新输出内容                                   │
│   ExecutionLog: 新增输出记录                                  │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 6. 判断任务状态                                              │
│                                                             │
│   系统动作：                                                  │
│   → 判断任务是否完成                                          │
│   → 判断是否需要 Handoff（额度不足、失败、需要其他 Agent）     │
│   → 判断是否需要调用工具（v0.1 暂不支持）                      │
│                                                             │
│   分支：                                                      │
│   ✅ 完成 → Task 状态: running → completed                   │
│   🔄 需要继续 → 保持 running，继续下一轮调用                  │
│   📤 需要交接 → 触发 Handoff 流程（流程 C）                   │
│   ❌ 失败 → Task 状态: running → failed                      │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 7. 结束 Session                                              │
│                                                             │
│   系统动作：                                                  │
│   → 更新 Worker Session 状态                                 │
│   → 记录结束时间                                              │
│   → 触发下一个 Task（如果有）                                  │
│   → 通知前端状态更新                                          │
└─────────────────────────────────────────────────────────────┘
```

## 流程 C：Handoff 任务交接

### 这是产品的核心差异化功能

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 触发交接                                                  │
│                                                             │
│   触发方式（三选一）：                                         │
│   方式 A：额度不足自动触发                                     │
│   → Quota Manager 检测到用量 ≥ 阈值的 80%                    │
│   → 标记为 warning 状态                                      │
│   → 自动触发 Handoff 流程                                    │
│                                                             │
│   方式 B：执行失败自动触发                                     │
│   → Agent 执行连续失败 N 次                                   │
│   → 模型返回错误或拒绝回答                                    │
│   → 自动触发 Handoff                                          │
│                                                             │
│   方式 C：用户手动触发                                         │
│   → 用户点击任务卡片上的「交接给其他 Agent」按钮                │
│   → 选择接手 Agent                                            │
│   → 手动触发                                                  │
│                                                             │
│   页面变化（Card Flow View）：                                 │
│   → 原 Agent Card：蓝色 → 紫色边框 + 状态灯                   │
│   → 两个 Agent Card 之间出现紫色动态连线 + Handoff Summary Card│
│   → 接手 Agent Card 状态变为 Loading                          │
│   → 底部日志区新增：「生成 Handoff Summary」                   │
│                                                             │
│   页面变化（Pixel Office View）：                              │
│   → 原 Agent 工位状态灯：蓝色 → 紫色闪烁                      │
│   → 原 Worker 生成 Handoff Folder 并拿起                     │
│   → 新 Worker 从大门进入                                      │
│   → Folder 沿贝塞尔曲线飞向新工位                             │
│   → Folder 交接动画                                           │
│   → 新工位状态灯变蓝，开始工作                                │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 2. 生成 Handoff Summary                                      │
│                                                             │
│   系统动作：                                                  │
│   → Summarizer Agent 启动                                    │
│   → 读取：当前 Goal、当前 Task、已完成内容、未完成内容、       │
│           约束条件、已做决策、遇到的问题、错误日志             │
│   → 生成结构化交接摘要                                        │
│                                                             │
│   摘要固定格式（必须一致，不然后续 Agent 读不懂）：             │
│   {
│     "original_goal": "原始目标",
│     "current_task": "当前任务描述",
│     "completed_work": ["已完成事项1", "已完成事项2"],
│     "unfinished_work": ["未完成事项1"],
│     "important_constraints": ["关键约束1"],
│     "key_decisions": ["已做决策1"],
│     "errors_and_risks": ["遇到的问题1"],
│     "next_suggested_steps": ["下一步建议1"],
│     "context_needed": ["接手 Agent 需要知道的上下文"]
│   }
│                                                             │
│   数据变化：                                                  │
│   → HandoffRecord 表新增记录                                  │
│   → Task.status: running → handoff                          │
│   → ExecutionLog: 新增「交接摘要生成」记录                     │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 3. 选择接手 Agent                                            │
│                                                             │
│   系统动作：                                                  │
│   → 自动模式：根据任务类型推荐最合适的 Agent + 模型            │
│   → 手动模式：用户选择接手 Agent                              │
│                                                             │
│   v0.1：默认手动选择，给用户推荐列表                           │
│                                                             │
│   页面变化：                                                  │
│   → 弹出交接确认弹窗                                           │
│   → 显示交接摘要预览                                           │
│   → 显示可接手的 Agent 列表（按推荐度排序）                    │
│   → 用户点击「确认交接」                                       │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 4. 执行交接                                                  │
│                                                             │
│   系统动作：                                                  │
│   → 旧 Worker Session：running → handoff_completed          │
│   → 旧 Agent Station：busy → idle                           │
│   → 创建新 Worker Session                                     │
│   → 新 Agent 加载 Handoff Summary 作为上下文                   │
│   → 新 Agent 开始执行任务                                      │
│                                                             │
│   页面变化：                                                  │
│   → 旧工位像素小人：将文件夹交给新工位小人（动画）              │
│   → 旧工位灯：紫色 → 灰色                                     │
│   → 新工位灯：灰色 → 紫色（短暂）→ 蓝色（开始工作）            │
│   → 任务卡片：紫色 → 蓝色                                     │
│   → 卡片上显示「已从 XX Agent 交接」标签                      │
│   → Handoff 页面新增一条交接记录                               │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 5. 交接完成                                                  │
│                                                             │
│   系统动作：                                                  │
│   → 更新 HandoffRecord：completed_at、result_after_handoff  │
│   → 记录交接耗时、交接前后 token 对比                          │
│                                                             │
│   用户可以：                                                  │
│   → 在 Handoff 页面查看交接历史                               │
│   → 对比交接前后的输出差异                                     │
│   → 将成功的交接保存为交接模板（未来功能）                      │
└─────────────────────────────────────────────────────────────┘
```

## 流程 D：查看 Agent 详情

### 方式一：Card Flow View 中点击卡片

```
用户操作：
1. 点击任意 Agent Card

系统响应：
→ 打开 Agent Detail Modal
→ 背景虚化
→ 其他卡片不可点击

Modal 中有 5 个 Tab：
- Overview：Agent 概览、当前模型、当前任务、Token 用量
- Task：任务描述、完成标准、依赖
- Context：Goal 上下文、Handoff 摘要
- Tools：工具权限、已调用工具记录
- History：执行历史、模型调用记录、错误记录

关闭方式：点击 X / 点击遮罩 / 按 Esc
```

### 方式二：Pixel Office View 中点击工位

```
用户操作：
1. 点击任意工位

系统响应：
→ 在像素场景中弹出 Station Popover
→ 不虚化整个场景
→ 其他区域仍然可见

Popover 内容（轻量级）：
- Station 名称
- Worker（当前模型）
- 当前 Task
- 当前状态
- 下一步动作
- 快捷按钮：View Full Detail / View Logs / Handoff / Pause

点击 View Full Detail：打开完整的 Agent Detail Modal
```

## 页面状态流转图

### Goal 状态流转

```
created → planning → in_progress → reviewing → completed
             ↓            ↓            ↓
           failed       failed       failed
```

### Task 状态流转（完整 9 种状态）

```
idle → queued → assigned → running → completed
                ↓         ↓
              waiting   handoff
                ↓         ↓
              running   assigned（新 Agent）
                ↓
            reviewing
                ↓
            completed

blocked / error → failed
```

### Agent Station 状态流转

```
idle → busy → idle
        ↓
      handoff → idle
```

## 异常流程

### 异常 1：模型调用失败

```
系统动作：
1. 记录错误日志
2. 自动重试最多 2 次
3. 仍失败：标记 Task 为 failed
4. 提示用户：可以换模型重试、或手动触发 Handoff

页面变化：
→ 任务卡片变红色
→ 显示错误信息
→ 显示「重试」「换模型」「交接」按钮
```

### 异常 2：用户中途关闭页面

```
系统动作：
1. 所有状态都已持久化到数据库
2. 用户重新打开后可以恢复
3. 支持「继续执行」或「终止」

页面变化：
→ 重新打开 Workspace 时自动恢复到上次状态
→ 显示「任务进行中，是否继续？」
```
