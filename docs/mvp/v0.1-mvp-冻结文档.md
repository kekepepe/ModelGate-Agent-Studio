# v0.1 MVP 冻结文档

> 🚧 **开发前必读**：本文档锁死 v0.1 的开发范围。任何不在本文档范围内的功能，一律推迟到后续版本。

## 一、MVP 核心定位

**ModelGate Agent Studio v0.1 = 多模型 Agent 协作工作台的最小可用版本**

- 不是万能 Agent
- 不是完全自动化开发工具
- 不是普通多 API 聊天工具
- 而是「任务拆解 → Agent 分工 → 状态记录 → Handoff 交接 → 可视化展示」的完整流程演示

---

## 二、v0.1 必须包含的功能 ✅

### 2.1 核心能力

| 功能 | 说明 | 完成标准 |
|------|------|----------|
| 用户输入 Goal | 用户可以输入任务目标 | 有输入框，能提交，能保存 |
| 任务拆解 | 将 Goal 拆成 3 个以上 Task | Planner Agent 输出结构化任务列表 |
| Agent 角色 | 支持至少 5 种 Agent Station | Planner / Coder / Reviewer / Summarizer / Supervisor |
| 模型配置 | 支持配置至少 3 种模型 | OpenAI / Anthropic / DeepSeek + Mock |
| 任务分配 | Task 可分配给不同 Agent | 任务卡片上显示 assigned_agent |
| 状态记录 | Agent 有 idle / working / completed 等状态 | 状态变化可被追踪 |
| 中间输出 | Agent 执行后有输出内容 | 每个 Task 有 output 字段 |
| Handoff Summary | 可以生成交接摘要 | 结构化输出交接内容 |
| 执行日志 | 所有操作有日志记录 | Logs 页面可查 |
| 最终汇总 | Supervisor 生成最终结果 | Goal 完成后有 summary |

### 2.2 页面范围

| 页面 | 优先级 | 核心功能 |
|------|--------|----------|
| Workspace | P0 | 任务卡片流、Agent 状态、双视图切换 |
| Dashboard | P1 | 概览、活跃 Goal、快速入口 |
| Agent Registry | P1 | Agent 列表、配置 |
| Models | P1 | 模型配置、API Key |
| Quota | P2 | 额度使用统计 |
| Handoff | P2 | 交接历史 |
| Logs | P2 | 执行日志 |

### 2.3 Workspace 双视图

```
┌─────────────────────────────────────────────────────────────┐
│  默认视图：Card Flow View                                    │
│  ┌──────────────────┐  ┌──────────────────┐                 │
│  │  Agent Card 1    │→│  Agent Card 2    │→ ...            │
│  │  [卡片颜色状态]   │  │  [卡片颜色状态]   │                 │
│  └──────────────────┘  └──────────────────┘                 │
│  ↓ 点击卡片 → 打开 Modal（5 个 Tab）                         │
│  - Overview / Task / Context / Tools / History              │
│                                                             │
│  底部：Completed Agents 缩略区 + Bottom Console（5 个 Tab）   │
└─────────────────────────────────────────────────────────────┘
          ↓ 切换按钮
┌─────────────────────────────────────────────────────────────┐
│  像素办公室视图：Pixel Office View                           │
│  [工位1]  [工位2]  [工位3]  [工位4]  [工位5]                │
│     ↓ 点击工位 → 打开 Station Popover（轻量详情）            │
│  - 不虚化背景，其他区域仍然可见                              │
│  - 快捷按钮：View Full Detail / View Logs / Handoff / Pause │
│                                                             │
│  Handoff 动画：文件夹沿贝塞尔曲线飞向新工位                   │
└─────────────────────────────────────────────────────────────┘
```

**重要架构原则**：
1. 两个视图共享同一套 `WorkspaceState` 数据
2. 不使用固定右侧详情面板，统一用：
   - Card Flow View：点击卡片 → 打开中心 Modal（带 Tab）
   - Pixel Office View：点击工位 → 打开 Station Popover
3. 连线样式：6 种（planned/active/done/handoff/error/waiting）
4. Agent 状态：9 种完整状态

## 三、v0.1 明确不做的功能 ❌

### 3.1 核心能力层

| 功能 | 不做的原因 | 推迟到 |
|------|-----------|--------|
| 真实复杂自动代码修改 | 涉及文件系统、权限、回滚、diff | v0.2+ |
| 完整 MCP 插件生态 | 架构复杂，前期不需要 | v0.3+ |
| 真实读取 Claude Code / Codex 额度 | API 不可控，技术难度高 | 长期 |
| 完整像素办公室动画 | 拖慢核心逻辑开发 | v0.2 优化 |
| 复杂 RAG 检索 | 先不做知识检索 | v0.2+ |
| 自动 Skill 沉淀 | Knowledge Evolution 后期做 | v0.3+ |
| 多人协作 | 单用户 MVP 足够 | 长期 |
| 企业权限管理 | 不需要 | 长期 |

### 3.2 Agent 层

| 功能 | 不做的原因 | 推迟到 |
|------|-----------|--------|
| Research Agent 真实网络搜索 | 需要爬虫/搜索 API | v0.2 |
| Agent 自动调用外部工具 | MCP 后期接入 | v0.3 |
| Agent 自动并行执行 | 先做串行流程 | v0.2 |
| 复杂任务依赖图 | 先做简单线性流程 | v0.2 |

### 3.3 Memory 层

| 功能 | 不做的原因 | 推迟到 |
|------|-----------|--------|
| 自动写入长期 Memory | 先做用户确认机制 | v0.2 |
| Memory 置信度评分 | 后期优化 | v0.3 |
| Memory 过期机制 | 后期优化 | v0.3 |
| Skill Library 自动生成 | 先做手动保存 | v0.2 |
| RAG 检索增强 | 先不加载历史记忆 | v0.2 |

### 3.4 部署与运维

| 功能 | 不做的原因 | 推迟到 |
|------|-----------|--------|
| 多端同步 | 本地先跑通 | 长期 |
| Docker 一键部署 | 开发阶段不需要 | v1.0 |
| 用户登录系统 | 本地单用户 | 长期 |
| 数据加密 | 本地数据不需要 | 长期 |

## 四、v0.1 的「伪实现」策略 🎭

为了快速验证产品逻辑，部分功能可以先做「伪实现」：

### 4.1 Agent Runtime 伪实现

```
真实状态系统 ✅
真实任务拆解 ✅（调用模型）
真实 Handoff Summary 生成 ✅（调用模型）
Agent 自动执行 → 先做半模拟
  - 状态变化真实
  - 输出可以是预设 + 部分真实调用
  - 不追求完全全自动跑完整流程
```

### 4.2 Quota Manager 伪实现

```
记录 token 使用量 ✅
记录调用次数 ✅
真实读取 Coding Plan 额度 → 手动配置
  - 用户可以设置每个模型的每日额度上限
  - 系统统计使用量
  - 达到阈值时触发 Handoff 提示
  - 支持手动「模拟额度不足」触发交接
```

### 4.3 模型调用伪实现

```
支持真实 API 调用 ✅
同时提供 Mock Model ✅
  - 不消耗 token
  - 快速验证流程
  - 固定输出模板
  - 用于 Demo 演示
```

## 六、核心对象的状态枚举 🔒

**开发前必须确认的状态值，之后不可随意增加。**

### Goal 状态

```typescript
type GoalStatus = 
  | 'created'      // 刚创建
  | 'planning'     // 正在拆解任务
  | 'in_progress'  // 执行中
  | 'reviewing'    // Supervisor 审查中
  | 'completed'    // 完成
  | 'failed'       // 失败
```

### Task 状态

```typescript
type TaskStatus = 
  | 'pending'      // 等待中
  | 'assigned'     // 已分配
  | 'running'      // 执行中
  | 'waiting'      // 等待依赖
  | 'handoff'      // 交接中
  | 'completed'    // 完成
  | 'failed'       // 失败
```

### Agent Station 状态（完整 9 种状态）

```typescript
type AgentStatus = 
  | 'idle'         // 空闲 - 灰色
  | 'queued'       // 排队中 - 黄色
  | 'running'      // 执行中 - 蓝色（呼吸动画）
  | 'waiting'      // 等待中 - 黄色（闪烁）
  | 'reviewing'    // 审查中 - 蓝色
  | 'handoff'      // 交接中 - 紫色
  | 'blocked'      // 阻塞中 - 橙色
  | 'error'        // 错误 - 红色
  | 'done'         // 完成 - 绿色
```

**状态-颜色映射：** 灰 → 黄 → 蓝 → 紫 → 绿 → 红 → 橙

### Worker Session 状态

```typescript
type WorkerStatus = 
  | 'idle'
  | 'running'
  | 'handoff_required'
  | 'completed'
  | 'failed'
```

## 七、开发顺序建议 📋

```
Phase 1: 数据层
├── 数据库 Schema
├── 基础 CRUD 接口
└── 状态系统

Phase 2: 核心流程
├── Goal 创建
├── Task 拆解
├── Agent 执行
└── Handoff 生成

Phase 3: Workspace 前端架构
├── WorkspaceState 核心状态层
├── View Adapter（CardFlowData / PixelOfficeData）
├── 卡片视图渲染器
└── 像素视图渲染器

Phase 4: 交互组件
├── Agent Detail Modal（5 个 Tab）
├── Station Popover（像素视图轻量详情）
├── Bottom Console（5 个日志 Tab）
├── Handoff Summary Card
└── Completed Agents 缩略区

Phase 5: 增强与收尾
├── 模型接入
├── 交接动画
├── Demo 流程脚本
└── 其他辅助页面
```

## 八、验收标准 ✅

v0.1 完成的标志是可以完整跑通这个 Demo：

```
1. 用户输入 Goal："帮我设计一个 Next.js + FastAPI 项目的 Workspace 页面"
2. 点击「开始」
3. Planner Agent 拆解成 4 个 Task
4. 任务卡片依次分配给 Coder、Backend、Reviewer
5. 每个 Agent 执行后更新状态和输出
6. 中途手动触发一次 Handoff
7. 生成 Handoff Summary
8. 接手 Agent 继续执行
9. Supervisor 生成最终汇总
10. Workspace 中可以看到完整的卡片流转和状态变化
11. Logs 页面可以看到完整执行记录
12. Handoff 页面可以看到交接记录
```

如果能完整跑完这个流程，v0.1 就算成功。

## 九、最后确认 📌

**开发过程中，如果遇到以下问题，按此原则处理：**

1. **这个功能很酷但不在 MVP 里？** → 记到「未来开发方向.md」，v0.1 不做
2. **实现复杂度超出预期？** → 降级为「伪实现」，保证流程通
3. **与现有设计冲突？** → 以本文档为准，修改设计文档
4. **想加新功能？** → 先完成 MVP，再加到下一个版本计划
