## 3. 保留但记录"暂时不能动"

### 3.1 `backend/src/services/providers/`（整个包，6 文件）

- **保留原因**：
  - 7 处生产代码引用：`review_service.py`、`model_orchestrator_service.py`、`runtime_service.py`、`embedding_service.py`、`model_gateway.py`、自己包内
  - 4 处测试引用：`test_mock_provider.py`、`test_runtime_e2e.py`、`test_model_orchestrator.py`、`conftest.py`
  - 是 V1.0-4 Runtime 引擎的**直接依赖**
- **什么时候可以删**：
  - 当 `runtime_service.py` / `orchestrator_service.py` 全部迁移到用新 `src/providers/` 时（V1.0-4 后期或 V1.0-5）
  - 迁移步骤：每个 service 改 import → 调新 provider → 跑测试 → 删老 import → 全部通过后整个 `services/providers/` 删
- **替代品**（已就绪）：
  - `src/providers/base.py` `LLMProvider` Protocol
  - `src/providers/litellm_provider.py` LiteLLM 实现
  - `src/providers/mock_provider.py` Mock 实现
- **两者协议差异**：
  - 老：`sync chat(prompt, model, system_prompt) -> str` + `configure_model(model_id, output_text_fn)`
  - 新：`async chat(messages: list[dict], model, *, tools=None, ...) -> dict` + `stream_chat` + `token_count`
  - 签名是破坏性变更，迁移需要改调用方

### 3.2 `backend/migrations/`（整个目录，9 SQL 文件）

- **保留原因**：
  - `tests/test_alembic_migrations.py::test_legacy_012_database_upgrades_without_losing_runtime_records` 引用这 9 个 SQL 做"老库升级"测试

## 6. V1.0-3.7 清理：删除 5 个 CI workflow

**删除 commit**：_下一个 commit_（V1.0-3.7）

**删除列表**（5 个，全在 `.github/workflows/`）：

| 文件 | 失败原因 | 何时可以恢复 |
|---|---|---|
| `backend-ci.yml` | 1. 引用 `python scripts/database_smoke.py` 路径错（实文件在 `backend/scripts/`）<br>2. 跑 `mypy` 但 venv 没装 mypy | V1.0-8 收尾时重写 |
| `frontend-ci.yml` | 强校验 `npm 10.9.8`，版本一变就挂 | 同上 |
| `integration-ci.yml` | 链式依赖 backend → backend 失败 → 整链失败 | 同上 |
| `nightly-ci.yml` | 3 个 job 包括 `live-provider-acceptance`，**必需要 5 个 GitHub Secrets**（PROVIDER_API_KEY 等），没有就在第一行 ::error fail-fast | V1.4+ 有真实 Provider 凭据时再启用 |
| `security-ci.yml` | `pip-audit --ignore-vuln` 用了 PYSEC-2026-xxx 硬编码 IDs，库升级后失效 | V1.0-8 收尾时重写 |

**总决策**：

> V1.0 阶段不跑任何 CI。所有质量门禁在本地跑（`pytest`、`npm run build` 等），V1.0-8 收尾时统一设计 V1.0 的正式 CI 集。

**恢复路径**（V1.0-8 时）：

- 参考设计 §8 V1.0 验收清单
- CI 必须通过才算 V1.0 发布
- 至少包含：后端 `pytest + ruff`、前端 `npm ci + lint + typecheck + build`、集成（API + 浏览器）
- live-provider 门禁放 nightly（V1.0 不强求）
