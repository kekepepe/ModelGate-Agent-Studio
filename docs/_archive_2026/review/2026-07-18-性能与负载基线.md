# ModelGate Agent Studio 性能与负载基线

日期：2026-07-18  
脚本：`backend/scripts/performance_baseline.py`  
生产基线数据库：PostgreSQL 16  
固定数据量：10 Goals、1000 Tasks、500 Execution Logs、100 Knowledge Chunks

## PostgreSQL 16 结果

| 场景 | 并发 | P95 | Error Rate | DB Queries / request |
|---|---:|---:|---:|---:|
| Workspace | 10 | 279.40 ms | 0 | 16 |
| Workspace | 25 | 380.85 ms | 0 | 16 |
| Workspace | 50 | 704.27 ms | 0 | 16 |
| 10 concurrent Goals | 10 | 140.42 ms | 0 | 16 |
| Retrieval | 50 | 597.52 ms | 0 | 12 |
| Scheduler, 1 Worker | 1 | 64.21 ms | 0 | 10 total/run |
| Scheduler, 3 Workers | 1 | 136.37 ms | 0 | 27 total/run |
| Scheduler, 5 Workers | 1 | 184.58 ms | 0 | 39 total/run |

Peak process memory was 111.88 MiB. Every Workspace and Retrieval P95 remained below the initial 1500 ms gate and every measured error rate was zero.

## Configuration and interpretation

- PostgreSQL uses `pool_pre_ping`, `DB_POOL_SIZE=20`, and `DB_MAX_OVERFLOW=30` by default; both pool values are configurable.
- The fixture exercises service-level database work without network or browser latency. It is a repeatable regression baseline, not an Internet-scale capacity claim.
- The UI regression suite separately renders a 100-task plan and paginates the 500-log fixture. A browser memory profiler and React render counter are still recommended before a public high-volume deployment.

## SQLite development limitation

The same 50-concurrency workload exceeded the 1500 ms P95 gate on SQLite (approximately 2.8 seconds). SQLite remains supported for single-user local development; it is not the production performance target. Production and load validation must use PostgreSQL.

## Reproduction

Use a disposable database whose URL contains `performance`; the script drops and recreates its tables.

```bash
cd backend
DATABASE_URL='postgresql+psycopg://modelgate:modelgate-test@127.0.0.1:55433/modelgate_performance' \
  .venv/bin/python scripts/performance_baseline.py
```
