## 归档原则

1. **不改不动**：归档文档保留原样，不修改也不删除内容（除非是空目录）
2. **git 历史可查**：所有 `git mv` 操作保留了完整文件历史
3. **新设计优先**：任何与新设计 `2026-09-06-platform-redesign.md` 冲突的内容，**以新设计为准**

## 为什么归档

项目从 2026-06 启动到 2026-09-06，经历 V0 / MVP / P0-P7 多轮迭代，沉淀了 100+ 份文档。  
2026-09-06 决定重设计（轻量化 + 现代栈 + Solo 友好），旧文档整体归档以：

- 减少新人/自己回顾时的认知负担
- 避免新旧文档混淆导致决策摇摆
- 把"权威来源"收敛到一份可被全文引用的设计文档
