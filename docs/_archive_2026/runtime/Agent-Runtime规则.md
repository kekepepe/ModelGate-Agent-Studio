# Agent Runtime 规则文档

> 🎯 **本文档定义 Agent 执行任务的标准流程和行为规范。**
>
> 这是整个系统的核心引擎，所有 Agent 的行为必须遵循这些规则。

## 二、Agent 执行标准流程

这是每个 Task 从开始到结束的完整生命周期。

```
┌─────────────────────────────────────────────────────────────┐
│  阶段 1：接收任务                                            │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  1.1 从 Task 队列取出待执行任务                               │
│      Task.status = pending → assigned                       │
│                                                              │
│  1.2 检查前置依赖                                            │
│      → 所有 dependencies 的 Task 都已完成？                   │
│      → 否：回到队列，稍后重试                                 │
│      → 是：继续                                              │
│                                                              │
│  1.3 加载 Agent Station 配置                                  │
│      → 读取 system_prompt                                    │
│      → 读取 allowed_tools                                     │
│      → 读取 default_model 和 backup_models                    │
│                                                              │
│  1.4 创建 Worker Session                                      │
│      WorkerSession.status = idle → running                   │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  阶段 2：上下文组装                                           │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  2.1 组装 System Prompt（Agent 角色）                         │
│                                                              │
│  2.2 组装 Task 描述 + 完成标准                                │
│                                                              │
│  2.3 附加上下文                                              │
│      → Goal 的原始描述                                        │
│      → 已完成 Task 的输出                                      │
│      → Handoff Summary（如果是交接来的）                       │
│      → v0.2+：相关 Memory 检索结果                             │
│                                                              │
│  2.4 组装输出格式要求                                         │
│      → 如果需要结构化输出，明确输出格式                         │
│                                                              │
│  2.5 生成最终的 Prompt 字符串                                 │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  阶段 3：模型选择与检查                                       │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  3.1 检查默认模型的额度状态                                    │
│      → 查询 QuotaUsage                                        │
│      → 检查是否接近或超过额度                                  │
│                                                              │
│  3.2 额度检查规则：                                           │
│      ✅ < 70%：正常使用默认模型                                │
│      ⚠️ 70%~90%：记录警告，继续使用                            │
│      ⚠️ 90%~100%：触发 Handoff 流程                            │
│      ❌ > 100%：立即触发 Handoff                               │
│                                                              │
│  3.3 如果需要 Handoff：                                       │
│      → 停止当前流程                                            │
│      → 调用 Handoff Manager                                   │
│      → 选择备用模型或其他 Agent                                │
│                                                              │
│  3.4 选定最终使用的模型 ID                                     │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  阶段 4：模型调用                                             │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  4.1 调用对应 Provider 的 API                                 │
│      → OpenAI / Anthropic / DeepSeek / Mock                  │
│                                                              │
│  4.2 超时与重试机制                                           │
│      → 超时时间：30 秒                                        │
│      → 最多重试：2 次                                         │
│      → 重试间隔：指数退避（1s, 2s, 4s）                       │
│                                                              │
│  4.3 记录调用结果                                             │
│      → 成功：记录 token 用量、耗时                              │
│      → 失败：记录错误信息、重试                                │
│      → 连续失败 2 次：触发 Handoff                             │
│                                                              │
│  4.4 更新 Quota 统计                                          │
│      → 更新 Model 表的 token 用量                              │
│      → 更新 QuotaUsage 日统计表                                │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  阶段 5：输出解析与处理                                       │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  5.1 解析模型返回的输出                                       │
│      → 提取思考过程（如果有）                                  │
│      → 提取最终答案                                            │
│      → 提取工具调用请求（v0.2+）                               │
│                                                              │
│  5.2 判断是否需要调用工具                                      │
│      → 是：执行工具调用 → 拿到结果 → 组装新 Prompt → 回到 4.1  │
│      → 否：继续                                               │
│                                                              │
│  5.3 更新 Worker Session 状态                                 │
│      → step_count += 1                                       │
│      → token_used += 本次用量                                 │
│      → 累积 output 内容                                       │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  阶段 6：完成判断与循环控制                                    │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  6.1 检查是否达到最大步数                                      │
│      → step_count >= max_steps_per_task？                    │
│      → 是：强制结束，标记完成或失败                            │
│                                                              │
│  6.2 判断任务是否完成                                          │
│      → Agent 输出明确表示完成？                                │
│      → 满足 completion_criteria？                             │
│      → Supervisor 审查通过？（v0.2+）                          │
│                                                              │
│  6.3 如果需要继续执行                                          │
│      → 组装下一轮 Prompt（包含历史对话）                       │
│      → 回到阶段 4，再次调用模型                                │
│                                                              │
│  6.4 如果完成                                                 │
│      → 继续到阶段 7                                            │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  阶段 7：结束与清理                                           │
└─────────────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────────────┐
│  7.1 更新 Task 状态                                          │
│      running → completed / failed                            │
│                                                              │
│  7.2 更新 Worker Session 状态                                │
│      running → completed / failed                            │
│                                                              │
│  7.3 记录最终统计数据                                         │
│      → 总耗时                                                 │
│      → 总 token 用量                                          │
│      → 总步数                                                 │
│                                                              │
│  7.4 释放 Agent Station                                       │
│      Agent.status = busy → idle                              │
│                                                              │
│  7.5 触发后续任务                                             │
│      → 检查是否有依赖此 Task 的其他 Task                       │
│      → 有：将其加入执行队列                                    │
│                                                              │
│  7.6 通知前端状态更新                                         │
│      → WebSocket 推送状态变更                                 │
└─────────────────────────────────────────────────────────────┘
```

## 三、Handoff 触发条件与流程

**Handoff 是本产品的核心差异化功能，必须严格执行。**

### 3.1 自动触发 Handoff 的条件

满足以下任一条件时，自动触发 Handoff：

| 条件 | 阈值 | 说明 |
|------|------|------|
| 模型 token 用量超额度 | ≥ 90% 当日限额 | QuotaManager 检查 |
| 模型请求次数超额度 | ≥ 90% 当日限额 | QuotaManager 检查 |
| 连续调用失败 | ≥ 2 次 | API 超时、报错等 |
| Agent 输出质量不达标 | Supervisor 判断 | v0.2+ |
| 任务类型与 Agent 能力不匹配 | Router 判断 | v0.2+ |

### 3.2 Handoff 执行流程

```
触发 Handoff
    ↓
暂停当前 Worker（不终止，保留上下文）
Task.status = running → handoff
    ↓
调用 Summarizer Agent 生成 Handoff Summary
    ↓
    │ 输入：
    │   - Goal 描述
    │   - Task 描述
    │   - 已完成的输出
    │   - Worker Session 历史
    │   - 错误日志（如果有）
    │   - 交接原因
    │
    ↓ 输出结构化的 HandoffSummary 对象
选择接手 Agent
    ↓
    │ 选择策略（v0.1 简化）：
    │   1. 同角色的其他 Agent（绑定不同模型）
    │   2. 额度充足的模型
    │   3. 用户手动选择
    │
    ↓
创建新 Worker Session
inherited_from_handoff_id = 当前 Handoff ID
    ↓
将 Handoff Summary 作为新 Worker 的初始上下文
    ↓
启动新 Worker 继续执行
    ↓
旧 Worker Session 标记为 handoff_completed
    ↓
记录完整的 HandoffRecord
    ↓
前端展示交接动画
```

### 3.3 Handoff 失败降级

如果 Handoff 过程中发生错误（如找不到可用的接手 Agent）：

```
降级策略：
1. 继续使用原模型（即使超额），记录警告
2. 提示用户手动选择接手 Agent
3. 暂停任务，等待用户干预
```

## 四、v0.1 Runtime 简化策略

为了快速交付 MVP，v0.1 对 Runtime 做以下简化：

### 4.1 简化项

| 功能 | v0.1 实现方式 | 完整实现（v0.2+） |
|------|--------------|------------------|
| 任务队列 | 简单的内存队列 | 持久化队列 + 优先级调度 |
| 并发 | 串行执行，一次跑一个 Task | 并行执行，Worker 池 |
| 工具调用 | ❌ 不实现 | 完整的 Tool Calling 层 |
| Supervisor 审查 | ❌ 不实现 | 自动审查机制 |
| Memory 检索 | ❌ 不实现 | RAG 检索相关 Memory |
| 自动任务依赖 | 简单顺序执行 | DAG 依赖调度 |

### 4.2 v0.1 的最小可用流程

```
用户点击开始
    ↓
Planner Agent 调用模型拆解 Task
    ↓
生成 3~5 个 Task（简化版，真实模型调用）
    ↓
Task 按顺序执行（串行）
    ↓
每个 Task：
    组装 Prompt
    调用模型
    拿到输出
    更新状态
    ↓
手动触发 Handoff 时：
    Summarizer 生成交接摘要
    用户选择接手 Agent
    新 Worker 继续
    ↓
所有 Task 完成
    ↓
Supervisor 生成最终汇总（可选）
```

## 五、Worker Session 必须记录的字段

每个 Worker Session 执行过程中，必须记录这些数据：

```typescript
interface WorkerExecutionRecord {
  // 执行标识
  worker_id: string;
  task_id: string;
  goal_id: string;
  agent_id: string;
  model_id: string;

  // 执行过程
  steps: {
    step_number: number;
    timestamp: Date;
    prompt: string;           // 本轮的 Prompt
    output: string;           // 本轮的输出
    tool_calls?: any[];       // 本轮的工具调用
    tokens_input: number;     // 输入 token
    tokens_output: number;    // 输出 token
    latency_ms: number;       // 耗时
    error?: string;           // 错误信息
  }[];

  // 汇总统计
  total_steps: number;
  total_tokens: number;
  total_duration_ms: number;
  total_tool_calls: number;
  total_errors: number;

  // 结果
  final_status: 'completed' | 'failed' | 'handoff';
  final_output?: string;
  error_message?: string;
  handoff_to_worker_id?: string;
}
```

**这些数据的重要性：**
1. 用于生成 Handoff Summary
2. 用于调试和排查问题
3. 用于分析各模型的表现
4. 用于未来优化路由策略

## 六、Runtime 配置参数

这些参数可以在配置文件中调整，无需改代码。

```typescript
interface RuntimeConfig {
  // 模型调用
  model_call_timeout_ms: number;           // 默认 30000
  model_call_max_retries: number;          // 默认 2
  model_call_retry_backoff_ms: number[];   // 默认 [1000, 2000, 4000]

  // 执行限制
  max_steps_per_task: number;              // 默认 5
  max_concurrent_workers: number;          // 默认 3（v0.1 设为 1）

  // Handoff 触发阈值
  handoff_token_usage_percent: number;     // 默认 90
  handoff_consecutive_errors: number;      // 默认 2

  // Quota 检查
  quota_check_interval_ms: number;          // 默认 60000（每分钟检查）

  // 超时
  worker_max_idle_time_ms: number;         // 默认 300000（5 分钟）
  task_max_total_time_ms: number;          // 默认 1800000（30 分钟）

  // 日志
  log_full_prompt: boolean;                 // 默认 false（生产环境不要打完整 Prompt）
  log_full_output: boolean;                 // 默认 false
}
```

## 七、错误处理与恢复机制

### 7.1 错误分类与处理策略

| 错误类型 | 处理策略 |
|---------|---------|
| 网络超时 | 重试 2 次，仍失败则触发 Handoff |
| API 返回错误（429 Rate Limit） | 立即触发 Handoff，标记模型不可用 |
| API 返回错误（401 Invalid Key） | 暂停任务，提示用户检查 API Key |
| API 返回错误（5xx Server Error） | 重试 2 次，仍失败则触发 Handoff |
| 输出解析失败 | 重试 1 次，提示模型按格式输出 |
| 上下文超长 | 触发 Handoff 给长上下文模型 |

### 7.2 崩溃恢复

Runtime 启动时：

```
1. 查询所有 status = running 的 Worker Session
2. 这些 Worker 是上次崩溃时未完成的
3. 逐个处理：
   - 执行时间 < 1 分钟：可能还能继续，尝试恢复
   - 执行时间 > 1 分钟：标记为 failed，提示用户
4. 提示用户有 N 个任务异常终止，是否重试
```

## 八、监控与可观测性

Runtime 必须暴露这些监控指标：

```
- 活跃 Worker 数量
- 队列中等待的 Task 数量
- 每分钟完成的 Task 数量
- 平均 Task 执行时间
- 平均 token 用量 / Task
- Handoff 触发频率
- Handoff 成功率
- 各模型的调用次数 / 成功率 / 平均耗时
- 错误率（按错误类型）
```

## 九、验收标准

Agent Runtime v0.1 完成的标志：

```
✅ 可以创建 Worker Session 并关联到 Task
✅ 可以组装 Prompt 并调用模型
✅ 可以解析模型输出并更新 Task
✅ 可以更新 token 用量和额度统计
✅ 可以记录完整的执行日志
✅ 可以手动触发 Handoff
✅ Handoff 时 Summarizer 可以生成结构化摘要
✅ 接手 Worker 可以基于摘要继续执行
✅ 可以处理 API 超时和重试
✅ 连续失败可以触发 Handoff
✅ 前端可以通过 WebSocket 收到状态更新
```
