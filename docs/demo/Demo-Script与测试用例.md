## 一、标准 Demo Script

**目标**：在 3-5 分钟内展示产品的核心差异化价值。

**核心叙事线**：
1. 这不是一个普通的聊天工具
2. 它可以把复杂目标拆成多个任务
3. 多个 Agent 分工协作
4. 遇到额度问题可以无缝交接
5. 整个过程可视化

---

### Demo 1：标准流程（4 分钟）

**场景**：用 ModelGate 设计一个前端页面。

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 1：输入目标（0:00 - 0:30）                             │
└─────────────────────────────────────────────────────────────┘

【操作】
1. 打开 Workspace 页面
2. 在左侧输入框输入：

"帮我设计一个 Todo List 应用的前端页面，用 React + Tailwind CSS。
要求：
- 可以添加、删除、标记完成
- 有筛选功能（全部/未完成/已完成）
- 有统计显示（总数/已完成/未完成）
- 响应式设计，支持移动端
- 美观现代的 UI"

3. 点击「开始」按钮

【展示点】
- 清晰的目标输入区
- 可以配置约束条件（可选）
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 2：任务拆解（0:30 - 1:30）                             │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. Planner Agent 开始工作（蓝色闪烁）
2. 生成 4 个 Task 卡片：
   - Task 1: 设计整体组件结构和数据流
   - Task 2: 实现核心 Todo 组件和状态管理
   - Task 3: 添加筛选和统计功能
   - Task 4: 代码审查与优化建议

3. 任务卡片依次出现，有动画效果

【展示点】
- Planner 理解目标并拆解任务
- 不是一次性输出，而是拆成多个步骤
- 每个任务有明确的负责 Agent
- 卡片视图清晰展示任务流程
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 3：Agent 执行（1:30 - 2:30）                           │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. Task 1 分配给 Planner Agent 执行
   - 卡片变蓝
   - 底部日志滚动
   - 执行完成后变绿

2. Task 2 分配给 Coder Agent 执行
   - 卡片变蓝
   - 生成 React 代码
   - 右侧显示代码输出
   - 执行完成后变绿

3. Task 3 继续执行...

【展示点】
- 每个 Agent 各司其职
- 状态实时更新
- 输出可以在右侧查看
- 完整的执行日志
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 4：切换像素视图（2:30 - 3:00）                         │
└─────────────────────────────────────────────────────────────┘

【操作】
1. 点击「视图切换」按钮
2. 切换到像素办公室视图

【展示点】
- 工位上的像素小人
- 状态灯显示工作状态
- 小人头顶显示模型名称
- 视觉化的协作过程
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 5：最终汇总（3:00 - 3:30）                             │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. 所有 Task 完成
2. Supervisor Agent 生成最终汇总
3. Goal 状态变为 completed（绿色）
4. 显示最终结果：完整的代码文件

【展示点】
- Supervisor 做最终验收
- 多个 Agent 的输出被整合成一个完整结果
- 用户拿到的是可以直接使用的成品
```

### Demo 2：Handoff 交接（2 分钟）

**场景**：展示核心差异化功能 - 任务交接。

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 1：模拟额度不足                                         │
└─────────────────────────────────────────────────────────────┘

【操作】
1. 正在执行 Task 的过程中
2. 手动点击「模拟额度不足」按钮
3. 或设置模型额度阈值很低，让系统自动触发

【系统行为】
1. 当前 Agent 停止工作
2. Task 状态变紫色
3. 显示「额度不足，正在生成交接摘要」
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 2：生成 Handoff Summary                                │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. Summarizer Agent 开始工作
2. 生成结构化的交接摘要：
   - 原始目标
   - 已完成内容
   - 未完成内容
   - 关键决策
   - 遇到的问题
   - 下一步建议

【展示点】
- 交接摘要是结构化的，不是简单的聊天记录
- 接手 Agent 不需要重新理解整个对话
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 3：交接动画                                             │
└─────────────────────────────────────────────────────────────┘

【系统行为】（像素视图中）
1. 原小人停下工作
2. 拿起一个文件夹
3. 文件夹飞向接手 Agent 的工位
4. 新小人接住文件夹
5. 开始继续工作

【展示点】
- 这是产品最有记忆点的动画
- 直观展示「交接」的概念
- 其他同类产品没有这个功能
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 4：继续执行                                             │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. 新 Agent 基于交接摘要继续执行
2. 不需要重新开始
3. 用户几乎感觉不到中断

【展示点】
- 交接后任务无缝继续
- 最终输出质量不受影响
- 用户不需要手动复制粘贴上下文
```

## 二、Demo 最佳实践

### 2.1 演示前准备

```
✅ 提前准备好 API Key，确保网络畅通
✅ 打开 DevTools 关掉网络节流（如果有）
✅ 提前跑一次 Demo，确认流程顺畅
✅ 如果网络不好，提前准备好录屏备用
✅ 打开全屏，关掉通知
```

### 2.2 演示话术建议

```
开场：
"很多 AI 工具都是单模型、单轮对话。但复杂任务往往需要：
1. 拆解成多个步骤
2. 不同步骤需要不同能力的模型
3. 中间可能中断需要继续

今天我要展示的 ModelGate Agent Studio，就是解决这个问题的。"

展示拆解时：
"你看，系统不是直接给答案，而是先把目标拆成具体的任务。
这就像一个技术主管在给团队分配工作。"

展示 Agent 协作时：
"每个任务由专门的 Agent 负责。
Planner 做规划，Coder 写代码，Reviewer 做审查。
这就是团队协作的 AI 版本。"

展示 Handoff 时：
"这是我们最核心的差异化功能：任务交接。
当某个模型额度用完、或者不适合继续时，
系统会自动生成交接摘要，把任务交给另一个模型。
整个过程用户不需要做任何操作。"

结尾：
"总结一下，这个产品解决了三个痛点：
1. 复杂任务不会一次聊完就断了
2. 多个模型可以真正协作，而不是简单切换
3. 额度、中断、换模型都不需要手动复制上下文"
```

### 2.3 常见问题准备

```
Q: 和 AutoGen / CrewAI 有什么区别？
A: 那些是开发者框架，我们是产品化的工作台，有可视化界面，开箱即用。

Q: 和 ChatGPT / Claude 有什么区别？
A: 单模型 vs 多 Agent 协作，就像一个人 vs 一个团队。

Q: 真的比直接用 Claude 好吗？
A: 对于简单问题，差不多。对于复杂、多步骤、需要持续的任务，这个模式更好。

Q: 支持哪些模型？
A: v0.1 支持 OpenAI、Anthropic、DeepSeek，以及兼容 OpenAI API 的所有模型。
```

## 四、MVP 验收标准

### 4.1 必须全部通过才能发布 v0.1

```
✅ 核心功能（全部 P0 用例通过）
  - TC001: 可以创建 Goal
  - TC002: 可以拆解任务
  - TC003: 可以执行 Task
  - TC004: 可以手动触发 Handoff

✅ 异常处理
  - TC101: API 错误不崩溃
  - 页面刷新不丢失数据

✅ UI 基础
  - TC201: 状态颜色正确
  - TC202: 点击交互正常

✅ Demo 流程
  - 可以完整跑完 Demo 1（标准流程）
  - 可以完整跑完 Demo 2（Handoff 交接）
```

### 4.2 发布质量要求

```
🔴 阻断级（不解决不能发布）：
  - 任何导致页面崩溃的 bug
  - 数据丢失的 bug
  - 核心流程无法走完

🟡 严重级（尽量修复）：
  - 偶发的异常
  - 明显的视觉 bug
  - 流程不顺畅

🟢 轻微级（可以后续修）：
  - 文案错误
  - 边缘情况的显示问题
  - 性能不影响使用的卡顿
```

## 五、Mock 数据 Demo 方案

如果后端还没开发完，可以用 Mock 数据做前端 Demo：

### 5.1 Mock 数据结构

```typescript
interface DemoState {
  currentStep: number;
  goal: Goal;
  tasks: Task[];
  agents: Agent[];
  logs: LogEntry[];
  handoffs: HandoffRecord[];
}
```

### 5.2 Demo 播放模式

```
添加一个「演示模式」开关：
- 开启后，所有模型调用都用 Mock 数据
- 按预设的时间间隔推进状态
- 可以「下一步」手动控制进度
- 用于没有网络 / 没有 API Key 时的展示

Demo 脚本是一个预先写好的 JSON 文件，
描述每个时间点应该更新什么状态、显示什么输出。
```
