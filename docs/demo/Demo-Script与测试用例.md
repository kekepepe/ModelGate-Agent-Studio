## 一、标准 Demo Script

**目标**：在 3-5 分钟内展示产品的核心差异化价值。

**核心叙事线**：
1. 这不是一个普通的聊天工具
2. 它可以把复杂目标拆成多个任务
3. 多个 Agent 分工协作
4. 遇到额度问题可以无缝交接
5. 整个过程可视化

---

### Demo 1：标准流程（4 分钟）

**场景**：用 ModelGate 设计一个前端页面。

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 1：输入目标（0:00 - 0:30）                             │
└─────────────────────────────────────────────────────────────┘

【操作】
1. 打开 Workspace 页面
2. 在左侧输入框输入：

"帮我设计一个 Todo List 应用的前端页面，用 React + Tailwind CSS。
要求：
- 可以添加、删除、标记完成
- 有筛选功能（全部/未完成/已完成）
- 有统计显示（总数/已完成/未完成）
- 响应式设计，支持移动端
- 美观现代的 UI"

3. 点击「开始」按钮

【展示点】
- 清晰的目标输入区
- 可以配置约束条件（可选）
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 2：查看可执行计划（0:30 - 1:00）                       │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. Workspace 创建串行的三步骤计划：
   - Step 1: Planner 明确交付物、约束和执行顺序
   - Step 2: Coder 实现主要方案或产出
   - Step 3: Reviewer 审查质量、遗漏和风险
2. 中心区以编号任务流显示三个步骤，而不是独立 Agent 工位或卡片网格。

【展示点】
- Goal 一开始就具有可理解、可执行、可追踪的协作路径。
- 每个步骤有明确的负责 Agent，且不会暗示当前尚不支持的并行或 DAG 调度。
- Task Card 显示模型、额度风险、输出、路由和交接信息。
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 3：顺序执行与审计（1:00 - 2:30）                       │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. Planner、Coder、Reviewer 按步骤执行；当前步骤的状态、模型和额度在同一张 Task Card 内更新。
2. 点击任意 Task，可在右侧查看 Router 决策、可继承 Context、Handoff Timeline 和最近日志。
3. 底部 Console 保留 Goal 级审计记录。

【展示点】
- 每个 Agent 各司其职，用户能知道每一步真实使用了哪个模型、为何选择、是否有风险。
- 输出与完整日志可在不离开 Workspace 的前提下查看。
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 4：最终结果（2:30 - 3:00）                             │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. 所有 Task 完成，Goal 状态变为 completed（绿色）。
2. Workspace 显示最终输出、完成 Task 数、Token 和日志数。
3. Supervisor Review 是运行后的质量检查；当前演示不把它描述为“拼接所有代码文件”的独立页面。

【展示点】
- 用户可判断执行结果、成本和审计轨迹，而不只看到一段模型输出。
```

### Demo 2：Handoff 交接（2 分钟）

**场景**：展示核心差异化功能 - 任务交接。

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 1：模拟额度不足                                         │
└─────────────────────────────────────────────────────────────┘

【操作】
1. 正在执行 Task 的过程中
2. 在该 Task Card 点击「交接任务」，或预先将当前模型额度设为 `limited` / `cooldown`。

【系统行为】
1. 当前 Task 进入 handoff 状态，并在同一条任务流中变为交接中。
2. Workspace 在 Task Card 和详情的 Handoff 标签中显示接手决定。
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 2：生成 Handoff Summary                                │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. 系统保存结构化的交接上下文：
   - 原始目标
   - 已完成内容
   - 未完成内容
   - 关键决策
   - 遇到的问题
   - 下一步建议

【展示点】
- 交接摘要是结构化的，不是简单的聊天记录
- 接手 Agent 不需要重新理解整个对话
```

```
┌─────────────────────────────────────────────────────────────┐
│  步骤 3：在同一 Workspace 中继续执行                          │
└─────────────────────────────────────────────────────────────┘

【系统行为】
1. 用户在 Handoff Sheet 中选择接手 Agent / 模型并接受交接。
2. 新 Worker 复用已确认的模型与继承上下文继续当前 Task。
3. 结果、额度、日志和 Handoff Timeline 都继续挂在原 Task 上。

【展示点】
- Handoff 是 Task 的连续执行状态，而不是跳转到独立管理页面。
- 用户不需要手动复制粘贴上下文，并可追溯完整交接记录。
```

## 二、Demo 最佳实践

### 2.1 演示前准备

```
✅ 提前准备好 API Key，确保网络畅通
✅ 打开 DevTools 关掉网络节流（如果有）
✅ 提前跑一次 Demo，确认流程顺畅
✅ 如果网络不好，提前准备好录屏备用
✅ 打开全屏，关掉通知
```

### 2.2 演示话术建议

```
开场：
"很多 AI 工具都是单模型、单轮对话。但复杂任务往往需要：
1. 拆解成多个步骤
2. 不同步骤需要不同能力的模型
3. 中间可能中断需要继续

今天我要展示的 ModelGate Agent Studio，就是解决这个问题的。"

展示拆解时：
"你看，系统不是直接给答案，而是先建立一个明确的串行协作计划。
这就像一个技术主管先给团队排好可执行的工作顺序。"

展示 Agent 协作时：
"每个任务由专门的 Agent 负责。
Planner 做规划，Coder 写代码，Reviewer 做审查。
这就是团队协作的 AI 版本。"

展示 Handoff 时：
"这是我们最核心的差异化功能：任务交接。
当某个模型额度用完、或者不适合继续时，
系统会生成交接摘要，并在同一个 Task 内展示接手选项。
用户可以确认接手 Agent / 模型；Provider 失败后的自动建议同样可追溯。"

结尾：
"总结一下，这个产品解决了三个痛点：
1. 复杂任务不会一次聊完就断了
2. 多个模型可以真正协作，而不是简单切换
3. 额度、中断、换模型都不需要手动复制上下文"
```

### 2.3 常见问题准备

```
Q: 和 AutoGen / CrewAI 有什么区别？
A: 那些是开发者框架，我们是产品化的工作台，有可视化界面，开箱即用。

Q: 和 ChatGPT / Claude 有什么区别？
A: 单模型 vs 多 Agent 协作，就像一个人 vs 一个团队。

Q: 真的比直接用 Claude 好吗？
A: 对于简单问题，差不多。对于复杂、多步骤、需要持续的任务，这个模式更好。

Q: 支持哪些模型？
A: v0.1 支持 OpenAI、Anthropic、DeepSeek，以及兼容 OpenAI API 的所有模型。
```

## 四、MVP 验收标准

### 4.1 必须全部通过才能发布 v0.1

```
✅ 核心功能（全部 P0 用例通过）
  - TC001: 可以创建 Goal
  - TC002: 可以创建串行协作计划
  - TC003: 可以执行 Task
  - TC004: 可以手动触发 Handoff

✅ 异常处理
  - TC101: API 错误不崩溃
  - 页面刷新不丢失数据

✅ UI 基础
  - TC201: 状态颜色正确
  - TC202: 点击交互正常

✅ Demo 流程
  - 可以完整跑完 Demo 1（标准流程）
  - 可以完整跑完 Demo 2（Handoff 交接）
```

### 4.2 发布质量要求

```
🔴 阻断级（不解决不能发布）：
  - 任何导致页面崩溃的 bug
  - 数据丢失的 bug
  - 核心流程无法走完

🟡 严重级（尽量修复）：
  - 偶发的异常
  - 明显的视觉 bug
  - 流程不顺畅

🟢 轻微级（可以后续修）：
  - 文案错误
  - 边缘情况的显示问题
  - 性能不影响使用的卡顿
```

## 五、Mock 数据 Demo 方案

如果后端还没开发完，可以用 Mock 数据做前端 Demo：

### 5.1 Mock 数据结构

```typescript
interface DemoState {
  currentStep: number;
  goal: Goal;
  tasks: Task[];
  agents: Agent[];
  logs: LogEntry[];
  handoffs: HandoffRecord[];
}
```

### 5.2 Demo 播放模式

```
添加一个「演示模式」开关：
- 开启后，所有模型调用都用 Mock 数据
- 按预设的时间间隔推进状态
- 可以「下一步」手动控制进度
- 用于没有网络 / 没有 API Key 时的展示

Demo 脚本是一个预先写好的 JSON 文件，
描述每个时间点应该更新什么状态、显示什么输出。
```
